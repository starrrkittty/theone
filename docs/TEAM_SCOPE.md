# 团队职责与接口边界

本页保留仓库最初的团队 TODO，并把 A/B/App 的交接关系写清楚。它是职责边界，不代表所有条目都已经完成。

## A：运动感知与数据底座（本仓库当前主线）

### 必须交付

- 姿态识别与关键点质量评估。
- 多人出现时的主体选择和干扰提示。
- 用户不选类型，由系统自动识别运动。
- 动作阶段识别，如下蹲、底部、起身、顶点或静态保持。
- URDF 读取、关节角、动作计数与运动学约束。
- 遮挡、低置信度和不可靠输入识别。
- 输出版本化结构化动作报告。

### 给 B 的接口

A 不把原始视频、完整关键点流或 URDF XML 直接交给大模型。统一输出 `ActionReport v1`：

```json
{
  "schema_version": "v1",
  "recognition_status": "confirmed",
  "recognized_exercise": "squat",
  "recognition_confidence": 0.92,
  "specialist": "squat_specialist",
  "phase": "bottom",
  "repetition": 8,
  "pose_quality": "good",
  "metrics": {"joint_angles": {}, "hold_seconds": 0.0},
  "violations": [],
  "agent_context": {
    "should_coach_now": false,
    "priority": "none",
    "recommended_intent": "observe"
  }
}
```

## B：智能教练、阶段规划与饮食规划

### 必须交付

- Agent Router：根据 A 的确认结果调用对应运动专项 Agent。
- 实时动作指导：结合连续错误、训练阶段和用户状态主动说话。
- 一个可运行的阶段训练计划模板，并支持周/日安排。
- 训练总结、基础饮食建议和安全提醒。
- 对话和复杂推荐由 LLM 完成，确定性数值计算沿用 A 的结果。

### 输入

- 用户画像和目标，由 App 提供。
- A 的 `ActionReport v1` 与识别事件。
- 训练历史和当前阶段计划。

### 输出

- 实时指导话术和专项 Agent 切换结果。
- 周/日训练计划、阶段总结和下一步建议。
- 与目标匹配的饮食建议及安全提醒。

## App：产品与交互

- 建立用户和 AI 私教的视频通话体验，管理音视频权限与会话。
- 从通话画面端侧提取骨架，向 A 发送骨架帧；默认不上传原始视频。
- 展示实时识别状态、次数、动作阶段、骨架叠加和纠错反馈。
- 承载训练计划、历史、饮食、榜单、激励和无障碍体验。
- 只保存业务所需数据；LLM API Key 由后端保管，不要求普通用户填写。

## 统筹与集成

- 冻结 A/B/App 的输入输出 Schema、错误码、版本和采样频率。
- 维护一套从视频通话到专项 Agent 回复的端到端回放样例。
- 预留不少于三天做权限、弱网、识别切换、音频打断和异常恢复联调。
